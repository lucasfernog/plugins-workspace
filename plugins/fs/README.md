## Install

_This plugin requires a Rust version of at least **1.77.2**_

There are three general methods of installation that we can recommend.

1. Use crates.io and npm (easiest, and requires you to trust that our publishing pipeline worked)
2. Pull sources directly from Github using git tags / revision hashes (most secure)
3. Git submodule install this repo in your tauri project and then use file protocol to ingest the source (most secure, but inconvenient to use)

Install the Core plugin by adding the following to your `Cargo.toml` file:

`src-tauri/Cargo.toml`

```toml
[dependencies]
tauri-plugin-fs = "2.0.0"
# alternatively with Git:
tauri-plugin-fs = { git = "https://github.com/tauri-apps/plugins-workspace", branch = "v2" }
```

You can install the JavaScript Guest bindings using your preferred JavaScript package manager:

```sh
pnpm add @tauri-apps/plugin-fs
# or
npm add @tauri-apps/plugin-fs
# or
yarn add @tauri-apps/plugin-fs
```

## Usage

First you need to register the core plugin with Tauri:

`src-tauri/src/lib.rs`

```rust
fn main() {
    tauri::Builder::default()
        .plugin(tauri_plugin_fs::init())
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
```

Afterwards all the plugin's APIs are available through the JavaScript guest bindings:

```javascript
import { stat } from '@tauri-apps/plugin-fs'

await stat('/path/to/file')
```

### Permissions and scope

Every command must be enabled in a [capability](https://v2.tauri.app/security/capabilities/), and every path it receives must be allowed by the fs scope.

`fs:default` only allows **reading** the application directories (`$APPCONFIG`, `$APPDATA`, `$APPLOCALDATA`, `$APPCACHE`, `$APPLOG`) recursively and creating them with `mkdir`, and denies the webview data stored in `$APPLOCALDATA` on Linux and Windows. Writing needs another permission, for example `fs:allow-app-write-recursive` for all the application directories or `fs:allow-appdata-write-recursive` for `$APPDATA` only. The `fs:allow-<dir>-<read|write|meta>[-recursive]` sets exist for every base directory variable below. See [`permissions/autogenerated/reference.md`](permissions/autogenerated/reference.md) for the full list.

A scope is a list of glob patterns, allowed or denied. It applies to every fs command when set on `fs:scope`, or to a single command when set on its permission:

```json
{
  "permissions": [
    "fs:default",
    {
      "identifier": "fs:scope",
      "allow": [{ "path": "$APPDATA/databases/**" }],
      "deny": [{ "path": "$APPDATA/databases/*.key" }]
    },
    {
      "identifier": "fs:allow-write-text-file",
      "allow": [{ "path": "$HOME/notes/*.md" }]
    }
  ]
}
```

- A pattern can start with a base directory variable: `$AUDIO`, `$CACHE`, `$CONFIG`, `$DATA`, `$LOCALDATA`, `$DESKTOP`, `$DOCUMENT`, `$DOWNLOAD`, `$EXE`, `$FONT`, `$HOME`, `$PICTURE`, `$PUBLIC`, `$RUNTIME`, `$TEMPLATE`, `$VIDEO`, `$RESOURCE`, `$TEMP`, `$APPCONFIG`, `$APPDATA`, `$APPLOCALDATA`, `$APPCACHE` and `$APPLOG`. `$DESKTOP`, `$EXE`, `$FONT`, `$RUNTIME` and `$TEMPLATE` do not exist on Android.
- `*` does not match path separators: `$APPDATA/*` allows the files directly in `$APPDATA`, `$APPDATA/**` everything below it. Neither matches `$APPDATA` itself, add it separately if the directory itself must be accessible (e.g. for `readDir`).
- Deny patterns take precedence over allow patterns.
- Matching is case-insensitive on every platform.
- On Unix, `*` and `**` do not match names starting with a `.`, so dotfiles must be named explicitly (see `requireLiteralLeadingDot` below).
- Existing symlinks are resolved before matching, so an existing path is checked against the location it points to.
- Paths may be absolute or relative to the `baseDir` option; `..` components are rejected.

From Rust, use `app.fs_scope()` (from `tauri_plugin_fs::FsExt`) to allow or forbid paths at runtime. The [dialog plugin](https://github.com/tauri-apps/plugins-workspace/tree/v2/plugins/dialog) does this for the paths the user picks. Paths dropped onto any window of the app (drag and drop) are also added to the scope, directories recursively.

### Configuration

```json
{
  "plugins": {
    "fs": {
      "requireLiteralLeadingDot": false
    }
  }
}
```

- `requireLiteralLeadingDot`: whether `*`, `?`, `**` and `[...]` must not match a leading `.` in a path component. Defaults to `true` on Unix and `false` on Windows.

### Cargo features

- `watch`: enables the `watch` command, used by the `watch` and `watchImmediate` JavaScript functions.

### Mobile

- On Android, the `content://` URIs returned by the dialog plugin can be read and written with `open`, `readFile`, `readTextFile`, `writeFile`, `writeTextFile`, `stat` and `lstat`. The other functions (`readDir`, `exists`, `remove`, `rename`, `copyFile`, `mkdir`, `truncate`, `size`, `readTextFileLines`, `watch`, ...) only support regular paths.
- `content://` URIs and bundled `$RESOURCE` files (`asset://localhost/`) are opened by the native layer and are **not** checked against the fs scope.
- On iOS, the plugin automatically starts accessing the security-scoped resource of a `file://` URL (e.g. one returned by the dialog plugin). Use `startAccessingSecurityScopedResource` and `stopAccessingSecurityScopedResource` to keep the access active across calls.
- From Rust, `app.fs().open(...)`, `read(...)` and `read_to_string(...)` open these paths too, which `std::fs` cannot do.
